Reading the numbers

What a 4-camera livestream needs

3DGS and SOG train every scene from scratch, so a live version needs a network trained once that builds each frame's scene in one pass. That is NPBG's e2e model today, or a feed-forward Gaussian model. Each stage below has to keep up every frame.

StageWhat it has to do liveNPBG todayA feed-forward Gaussian route
CaptureGrab 4 synchronized framesDone; frames land within about 20 ms of each otherSame rig, same code
Camera posesKnown for every frameFree: the rig is calibrated and doesn't moveSame
Depth / geometryPer frame, fastFoundationStereo, about 80 ms of GPU time; the current bottleneckMany of these models predict their own depth, so FoundationStereo might be dropped or used as a hint
Scene buildOne network passAbout 19 ms (e2e model)One network pass; speed depends on the model
Compression and streamingSend each frame's scene over the networkCompact format designed (8-bit descriptors, 16-bit depth), about 1–2 Gbps at 15 fps by a rough estimateGaussians are larger per point. SOG's compression sorts and encodes each scene and was built for offline use, so it would need a real-time replacement.
Rendering on the viewer30–90 fps on the viewer's device20–35 fps at 1080p on a 4090, because of the decoderPlain rasterization, hundreds of fps, even on weaker GPUs

NPBG's live numbers (capture skew, FoundationStereo cost, 19 ms scene build) come from NPBG's REALTIME_PIPELINE.md on two RTX 4090s, not from this benchmark. The bandwidth figure is an estimate, not a measurement. The feed-forward Gaussian column has not been tested here yet.
